# Product Requirements Document (PRD): ระบบจองห้องประชุมและยานพาหนะ (Meeting Room & Vehicle Reservation)

## 1. วัตถุประสงค์ (Objective)
พัฒนาระบบบริหารจัดการและจองทรัพยากรส่วนกลางของคณะ ได้แก่ ห้องประชุม อุปกรณ์โสตทัศนูปกรณ์ และยานพาหนะส่วนกลาง เพื่อเพิ่มประสิทธิภาพในการใช้งาน ลดความผิดพลาดจากการจองซ้ำซ้อน (Double Booking) และอำนวยความสะดวกในการติดตามสถานะคำขอแบบดิจิทัล

## 2. กลุ่มผู้ใช้งาน (User Personas & Roles)
1. **บุคคลทั่วไป / นักศึกษา / คณาจารย์ (Guest / Public Users):** ตรวจสอบตารางการใช้ห้องประชุมและรถยนต์ ความพร้อมใช้งาน และคุณสมบัติของห้อง/รถ ผ่าน Public Portal
2. **คณาจารย์และบุคลากร (Staff / Faculty Members):** ยื่นคำขอจองห้องประชุมและรถยนต์ส่วนกลาง ติดตามสถานะคำขอ และยกเลิกการจองของตนเอง
3. **เจ้าหน้าที่อาคารสถานที่และยานพาหนะ (Facility / Fleet Officers):** ตรวจสอบคำขอ, พิจารณาอนุมัติ/ไม่อนุมัติ, ตรวจสอบตารางเวลา และจัดสรรยานพาหนะพร้อมคนขับ
4. **ผู้ดูแลระบบ (Admin / Super Admin):** จัดการทะเบียนห้องประชุม ยานพาหนะ กำหนดความจุ อุปกรณ์ และดูรายงานสถิติภาพรวม

## 3. Functional Requirements
- **FR-01 ทะเบียนห้องประชุม (Meeting Rooms):** บันทึกรหัสห้อง, ชื่อห้อง (ไทย/อังกฤษ), อาคาร, ชั้น, ความจุ, ประเภทห้อง, สิ่งอำนวยความสะดวก (โปรเจคเตอร์, ระบบประชุมทางไกล, เครื่องเสียง), และรูปภาพ
- **FR-02 ทะเบียนยานพาหนะ (Vehicles):** บันทึกทะเบียนรถ, ยี่ห้อ/รุ่น, ประเภทรถ (รถตู้, รถเก๋ง, SUV, บัส), จำนวนที่นั่ง, ชื่อคนขับ, เบอร์ติดต่อ, และรูปภาพ
- **FR-03 ยื่นคำขอจอง (Resource Booking):** เลือกระบุห้องหรือยานพาหนะ, วันเวลาเริ่มต้นและสิ้นสุด, วัตถุประสงค์, จำนวนผู้ใช้, ข้อมูลผู้ติดต่อ, จุดหมายปลายทาง (สำหรับรถ), ความต้องการคนขับ, และคำขอพิเศษ
- **FR-04 ป้องกันการจองซ้อน (Conflict Detection):** ตรวจสอบช่วงเวลาซ้ำซ้อน (`[startDateTime, endDateTime]`) กับรายการที่มีสถานะ `APPROVED` หรือ `PENDING` อย่างแม่นยำ
- **FR-05 พิจารณาคำขอ (Approval Workflow):** เจ้าหน้าที่สามารถกดอนุมัติ หรือไม่อนุมัติพร้อมระบุเหตุผลได้ทันที
- **FR-06 ปฏิทินและตารางการใช้งาน (Calendar & Schedule Grid):** แสดงมุมมองตารางเวลาทั้งแบบรายวันและรายสัปดาห์
- **FR-07 รหัสใบจองอัตโนมัติ (Booking Code Sequence):** สร้างรหัสอัตโนมัติ เช่น `BK-2569-0001`
- **FR-08 Audit Trail:** บันทึกประวัติการอนุมัติ ไม่อนุมัติ และยกเลิกลงตาราง `audit_logs`

## 4. Acceptance Criteria
- ผู้ใช้ไม่สามารถจองห้องหรือรถในช่วงเวลาที่ทับซ้อนกับการจองที่ได้รับอนุมัติแล้วได้
- หน้า Public Portal แสดงสถานะความพร้อมใช้งานและตารางการใช้ได้อย่างถูกต้องโดยไม่ต้องล็อกอิน
- เจ้าหน้าที่สามารถจัดการสถานะห้อง/รถ (พร้อมใช้งาน, ปรับปรุง, ปิดใช้งาน) ได้
- ผ่าน Quality Gates: TypeScript, ESLint, Dependency-Cruiser และ Unit Tests 100%
